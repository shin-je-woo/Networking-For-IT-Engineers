# 08. 서버 네트워크 기본

## **8.1 서버의 네트워크 설정 및 확인**

- 서버가 서비스(애플리케이션)를 제공하려면 네트워크 연결이 전제되어야 한다.
- 장애 원인이 네트워크인지 서버인지 빠르게 구분하려면 서버 관점에서 기본 설정과 확인 방법을 알아야 한다.
- 이번 절은 Windows 서버와 Linux 서버에서 IP, 서브넷 마스크, 게이트웨이, DNS 같은 필수 값을 설정하고 현재 값을 확인하는 방법을 다룬다.

### **8.1.1 리눅스 서버 네트워크**

- 공통 관점
    - Linux는 설정 파일을 편집해 네트워크를 구성하는 방식이다.
    - 배포판마다 설정 파일 위치와 형식이 다를 수 있다.
- CentOS의 네트워크 설정
    - ONBOOT: 부팅 시 해당 인터페이스를 올릴지 여부
    - BOOTPROTO: IP 할당 방식 선택, none static dhcp 같은 값 사용
    - IPADDR: IP 주소
    - NETMASK 또는 PREFIX: 서브넷 마스크를 점 표기 또는 프리픽스 길이로 표현
    - GATEWAY: 기본 게이트웨이
    - DNS1 DNS2: DNS 서버 주소
    - DEFROUTE: 기본 라우팅을 만들지 여부에 영향을 주는 설정
- 우분투의 네트워크 설정
    - 기본적인 네트워크 설정은 CentOS와 비슷하다.
    - 설정 파일 안에서 인터페이스별로 static 또는 dhcp 같은 방식으로 설정이 가능하다.
    - CentOS처럼 인터페이스마다 파일이 쪼개져 있지 않고 한 파일에 작성하는 것이 차이점이다.

### **8.1.2 윈도 서버 네트워크**

- GUI로 설정
    - 네트워크 연결 화면에서 어댑터를 선택
    - IPv4 속성에서 IP, 서브넷 마스크, 기본 게이트웨이, DNS를 설정
- 현재 설정 확인
    - ipconfig로 기본 정보 확인
    - ipconfig /all로 상세 정보 확인 → MAC 주소, DNS, DHCP 사용 여부 같은 값까지 확인 가능

## **8.2 서버의 라우팅 테이블**

- 네트워크 장비뿐 아니라 서버도 외부 네트워크와 통신하기 위해 라우팅 테이블을 가진다.
- 라우팅 정보를 별도로 설정하지 않더라도 네트워크 정보를 설정할 때 IP 주소, 서브넷 마스크, 기본 게이트웨이 주소를 입력하면 기본 라우팅이 라우팅 테이블에 자동으로 등록된다.
- 네트워크 어댑터를 두 개 이상 사용하는 구성에서는 추가 고려가 필요하다.
- 예를 들어, 웹 서비스용 프론트엔드 네트워크와 백엔드 네트워크를 분리하는 경우처럼 서버에 서로 다른 네트워크를 동시에 연결할 수 있다.
- 공인망과 통신해야 하는 프론트엔드 네트워크 쪽 어댑터에만 기본 게이트웨이를 설정하고 백엔드 네트워크 쪽은 목적지에 맞는 라우팅 정보를 별도로 설정해야 한다.

### **8.2.1 서버의 라우팅 테이블**

<img width="613" height="147" alt="image" src="https://github.com/user-attachments/assets/fd0348ba-277b-487c-81a0-1c306b9e8268" />

- 라우팅 테이블에서 확인할 주요 항목은 다음과 같다.
    - 목적지(Destination)
    - 서브넷(Genmask)
    - 게이트웨이(Gateway)
    - 인터페이스(Iface)
    - 우선순위(Metric)
- 목적지 네트워크와 서브넷 정보는 서버가 통신하려는 목적지 IP 주소가 어느 네트워크 범위에 속하는지 판단하는 기준이 된다.
- 게이트웨이는 목적지로 가기 위해 서버가 선택하는 넥스트 홉이다.
- 목적지 경로가 연결(connected)로 표시되는 경우는 로컬 네트워크이므로 해당 네트워크에서 바로 통신한다.
- 서버에 두 개 이상의 네트워크 카드가 있다면 목적지에 맞는 네트워크 카드의 게이트웨이를 지정해야 한다.
- 인터페이스는 서버가 패킷을 어떤 물리적인 경로로 내보낼지를 결정하는 값이다.
- 우선순위는 동일한 목적지 라우팅 정보가 둘 이상 존재할 때 어떤 라우팅 정보를 사용할지 결정하는 값이다.
- 우선순위 값이 낮을수록 우선순위가 높다.

### **8.2.2 리눅스 서버의 라우팅 확인 및 관리**

- 리눅스에서 라우팅 테이블을 확인하기 위해 `ip route` 명령을 사용한다.
- 라우팅 테이블 결과는 `ip route` 외에도 `netstat -r` 옵션으로 확인할 수 있다.
- 출력 형식은 다를 수 있으나 라우팅 테이블의 의미는 동일하다.
- 서버의 네트워크 인터페이스가 한 개뿐이라면 라우팅 테이블을 추가하거나 삭제할 필요가 거의 없다.
- 네트워크 인터페이스가 두 개 이상으로 구성되면 어떤 인터페이스를 통해 패킷을 전송할 것인지 명시해야 하므로 라우팅 정보를 조정하거나 관리해야 한다.

### **리눅스 라우팅 추가**

- 리눅스에서 라우팅 테이블을 추가하는 명령 형식은 다음과 같다.
    - route add { -host | -net } Target[/prefix] [ gw Gw ] [ metric M ] [[ dev ] If ]
- 목적지가 단일 호스트라면 -host로 등록한다.
- 목적지가 네트워크 대역이라면 -net으로 등록한다.
- 필요하면 metric 값을 부여해 우선순위를 조정한다.
- metric 값이 작은 라우팅이 액티브 경로가 되고 metric 값이 큰 라우팅은 스탠바이 경로가 된다.
- 액티브 경로에 문제가 생기면 라우팅 테이블에서 해당 경로가 사라지며 스탠바이 경로로 통신이 페일오버된다.
- 영구 적용은 라우팅 설정 파일에 적용한다.

### **리눅스 라우팅 삭제**

- 리눅스에서 라우팅 테이블을 삭제하는 명령 형식은 다음과 같다.
    - route del { -host | -net } Target[/prefix] [ gw Gw ] [ metric M ] [[ dev ] If ]
- 라우팅 삭제는 라우팅 추가와 유사한 형태로 수행한다.
- 디폴트 라우팅은 목적지를 default로 지정해 추가하거나 삭제할 수 있다.
- 영구 적용은 라우팅 설정 파일에 적용한다.

### **8.2.3 윈도 서버의 라우팅 확인 및 관리**

- 윈도 서버에서 라우팅 테이블을 확인하고 관리하기 위해 `route` 명령을 사용한다.
- route 명령에서 사용하는 주요 옵션은 다음과 같다.
    - PRINT
    - ADD
    - DELETE
    - CHANGE
- `route print`로 라우팅 테이블을 출력하면 인터페이스 목록을 확인할 수 있다.
- 라우팅 테이블에는 현재 활성 경로(Active Routes)가 표시된다.
- 하단의 영구 경로(Persistent Routes)는 서버가 재부팅되어도 지속적으로 유지되는 라우팅 정보다.
- 윈도에서는 라우팅을 추가할 때 -p 옵션을 사용하면 영구 경로로 등록할 수 있다.
- 라우팅을 삭제할 때는 목적지 네트워크, 서브넷 마스크, 게이트웨이 조합에 따라 여러 항목이 함께 삭제될 수 있으므로 주의해야 한다.
- 라우팅을 변경할 때는 필요한 정보를 모두 정확히 입력해야 한다.

## 8.3 네트워크 확인을 위한 명령어

- 서버를 처음 네트워크에 연결할 때 설정이 올바른지 확인이 필요하다.
- 운영 중 통신 장애나 서비스 장애가 발생했을 때 원인을 빠르게 좁히는 접근이 필요하다.
- 단일 명령으로 결론을 내리기보다 여러 명령을 조합해 원인을 분석하는 접근이 필요하다.

### 8.3.1 ping(Packet InterNet Groper)

- 목적
    - IP 계층 기준으로 목적지까지 도달 가능한지 확인한다.
    - 왕복 지연 시간 RTT와 패킷 손실 여부를 통해 네트워크 품질을 가늠한다.
- 특성
    - ICMP 제어 메시지를 사용한다.
    - 목적지 호스트가 ICMP를 차단하면 서비스가 정상이어도 ping은 실패할 수 있다.
    - 기본 ping만으로는 서비스 포트가 열려 있는지까지 확인할 수 없다.

### 8.3.2 tcping(윈도)

- 목적
    - ICMP가 차단된 환경에서 TCP 기반으로 목적지 서비스 포트가 열려 있는지 확인한다.
    - Port is open 같은 결과와 함께 응답 시간도 확인한다.
- 사용 시점
    - ping은 성공하지만 실제 서비스 접속이 안 될 때 서비스 포트 단의 문제를 확인한다.
    - 방화벽 정책이나 서비스 리스닝 상태를 확인할 때 유용하다.

### 8.3.3 traceroute(리눅스)/tracert(윈도)

- 목적
    - 출발지에서 목적지까지의 네트워크 경로를 홉 단위로 추적한다.
    - 어느 구간부터 지연이나 단절이 발생하는지 범위를 좁힌다.
- 동작 원리
    - IP 헤더의 TTL 값을 1부터 증가시키며 패킷을 보내고 중간 장비의 ICMP 응답을 이용해 경로를 추적한다.
    - 라우터나 L3 장비 수준의 경로 확인에 유효하다.
- 해석 포인트
    - 중간 홉에 별표가 출력될 수 있다.
        - 중간 보안 장비가 ICMP 또는 UDP 응답을 차단하는 경우다.
        - 차단되었더라도 다음 홉이 보이면 경로 자체가 완전 단절은 아닐 수 있다.
    - 비대칭 경로 가능성이 있다.
        - 서버1에서 서버2로 가는 경로와 서버2에서 서버1로 가는 경로가 다를 수 있다.
        - 방화벽이나 정책 라우팅에 의해 한 방향만 차단되는 형태가 발생할 수 있다.

### 8.3.4 tcptraceroute

- 목적
    - traceroute의 경로 추적에 서비스 포트 확인 개념을 결합한다.
    - 목적지까지 특정 서비스 포트가 실제로 열려 있는지 경로와 함께 확인한다.
- 장점
    - 중간 경로에서 차단인지 목적지 서비스 포트 차단인지 구분하는 데 도움이 된다.

### 8.3.5 netstat(network statistics)

- 목적
    - 서버의 포트 상태와 연결 상태를 확인한다.
        - LISTENING 상태인지
        - ESTABLISHED 같은 세션 상태가 어떤지
        - TIME_WAIT 같은 종료 관련 상태가 누적되는지
    - 라우팅 테이블과 인터페이스 통계 등도 함께 확인할 수 있다.
- 사용 관점
    - 현재 열려 있는 서비스 포트를 빠르게 확인할 때 유용하다.
    - 출력이 많을 때 특정 문자열로 필터링해 필요한 항목만 본다.

### 8.3.6 ss(socket statistics)

- 목적
    - netstat 대체 용도로 소켓 정보를 더 빠르고 다양하게 확인한다.
- 특징
    - 필터링 기능을 기본 제공해 필요한 상태만 골라 보기 쉽다.
    - state 필터로 established, listen 등 연결 상태 기준 조회가 가능하다.
    - 프로세스 정보까지 함께 확인해 어떤 프로세스가 포트를 점유하는지 확인한다.

### 8.3.7 nslookup(name server lookup)

- 목적
    - DNS 서버에 질의해 도메인 관련 정보를 확인한다.
    - 특정 도메인의 IP 확인뿐 아니라 레코드 타입별 조회가 가능하다.
- 사용 관점
    - 기본 DNS 설정으로 질의한다.
    - 필요 시 질의할 DNS 서버를 지정해 외부 전파 여부나 특정 DNS 응답을 비교한다.
    - set type으로 A, AAAA, MX, NS, PTR 같은 레코드를 확인한다.

### 8.3.8 telnet(tele network)

- 목적
    - 원격 터미널 접속 용도로 오래 사용된 표준 프로토콜이다.
    - 네트워크 점검 관점에서는 특정 서비스 포트가 열려 있는지 확인하는 용도로도 사용한다.
        - 예: telnet 대상 도메인 80
- 보안 관점
    - 평문 통신이므로 실무에서는 보안상 SSH 사용이 권장된다.
- 연결이 안 될 때 자주 나오는 원인 범주
    - 목적지 단말이 꺼져 있거나 네트워크에 정상 연결되어 있지 않다.
    - 목적지 단말의 네트워크 설정에 문제가 있다.
    - 출발지에서 목적지까지의 경로가 정상적이지 않다.
    - 중간 보안 장비나 목적지 방화벽 정책으로 차단된다.
    - 목적지에서 서비스가 리스닝 상태가 아니거나 다른 포트로 서비스가 올라가 있다.

### 8.3.9 ipconfig

- 목적
    - 윈도에서 네트워크 설정과 상태를 확인하고 DHCP 관련 동작을 제어한다.
- 자주 쓰는 기능
    - DHCP 환경에서 현재 IP를 해제하고 갱신한다.
        - release
        - renew
    - DNS 확인자 캐시를 삭제한다.
        - flushdns
    - 로컬 DNS 캐시 정보를 확인한다.
        - displaydns

### 8.3.10 tcpdump

- 목적
    - 네트워크 인터페이스로 오가는 패킷을 캡처해 분석한다.
    - 장애 상황에서 패킷 단위 근거를 확보할 때 유용하다.
- 사용 관점
    - 인터페이스를 지정해 캡처한다.
    - host, src, dst, port, tcp, udp 같은 조건으로 필요한 트래픽만 필터링한다.
    - not, and, or로 조건을 조합해 잡음을 줄인다.
    - 출력이 많으면 파일로 저장해 와이어샤크 같은 분석 도구로 연다.
