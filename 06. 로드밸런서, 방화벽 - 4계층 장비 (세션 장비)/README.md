# 06. 로드 밸런서/방화벽: 4계층 장비(세션 장비)

## 6.1 4계층 장비의 특징

- 2계층, 3계층 장비는 MAC, IP 중심으로 판단한다.
- 4계층 장비는 TCP와 같은 헤더에 있는 정보를 이해하고 이 정보들을 기반으로 동작한다.
- 핵심 개념은 세션 기반 처리
    - 통신의 상태를 기록하고 그 기록을 기준으로 다음 패킷을 허용하거나 차단한다.
    - 이 기록 저장소가 세션 테이블(Session Table)이다.
- 세션 테이블은 메모리를 쓰기 때문에 운영에서 타임아웃이 매우 중요하다.
    - 타임아웃이 짧으면 정상 통신도 끊길 수 있다.
    - 타임아웃이 길면 세션이 쌓여 메모리가 고갈될 수 있다.
- 로드 밸런서, 방화벽은 대표적인 세션 장비다.

## 6.2 로드 밸런서

- 목적은 서버 부하 분산, 장애 시 우회, 확장 지원이다.
- 사용자 입장에서는 하나의 서비스로 보이게 만들고, 내부에서는 트래픽을 여러 서버로 분산한다.
- 서비스 IP(VIP)를 두고 실제 서버(Real Server)로 트래픽을 전달한다.
- L4 로드 밸런싱
    - 일반적인 로드 밸런서가 동작하는 방식
    - TCP, UDP 정보(특히 포트 넘버)를 기반으로 로드 밸런싱 수행
    - 4계층에 대한 정보로만 분산 처리하는 경우를 L4 로드 밸런싱이라고 한다.
- L7 로드 밸런싱
    - HTTP, FTP, SMTP와 같은 애플리케이션 프로토콜 정보를 기반으로 로드 밸런싱 수행
    - HTTP 헤더 정보나 URI와 같은 정보를 기반으로 부하를 분산
    - 일반적으로 이런 장비를 ADC(Application Delivery Controller)라고 부르며 프록시 역할을 수행한다.

### 6.2.1 L4 스위치

- L4 스위치는 말 그대로 4계층에서 동작하면서 로드 밸런서 기능이 있는 스위치이다.
- 구성 개념
    - VIP: 사용자가 접속하는 서비스 IP
    - Virtual Server: VIP와 포트 조합으로 정의되는 서비스 단위
    - Real Server: 실제 처리 서버와 그 IP
- L4 스위치는 가상 IP를 리얼 IP로 다시 변경해 보내준다.

### 6.2.2 ADC

- 애플리케이션 계층까지 이해하고 더 적극적으로 개입하는 장비다.
- L4 분산에 더해 기능 범위가 넓다.
    - 캐싱: 정적 리소스를 장비가 대신 응답해 서버 부하를 줄인다.
    - 압축: 응답을 압축해 전송량과 서버 CPU 사용을 줄인다.
    - SSL 오프로딩: 암복호화를 장비가 맡아 웹 서버 부담을 줄인다.
    - 리다이렉션, 콘텐츠 변환, 재작성 같은 애플리케이션 최적화
    - 장애 복구(Failover)
    - 보안 확장으로 WAF(Web Application Firewall) 같은 기능이 붙을 수 있다.

### 6.2.3 L4 스위치 vs ADC

- L4 스위치
    - TCP, UDP, 포트 정보를 기반으로 부하 분산
    - TCP 레벨 최적화가 붙을 수 있다. (커넥션 풀, TCP 세션 재사용 등)

## 6.3 방화벽

- 장비를 통과하는 트래픽을 정책에 따라 허용 또는 차단하는 장비다.
- 보통 3계층, 4계층에서 동작하며 세션을 인지하는 SPI(Stateful Packet Inspection) 엔진을 기반으로 동작하는 장비를 방화벽이라고 한다.
- 패킷이 외부로 나갈 때 세션 정보를 저장하고, 세션 테이블에 기록된 요청 또는 응답 패킷이면 통과시키고, 아니면 정책으로 판단한다.
- NAT와 유사하게 상태를 저장하고 그 상태로 판단하는 점이 중요하다.
- 상태 테이블, 세션 테이블은 같은 맥락의 용어로 쓰인다.

## 6.4 4계층 장비를 통과할 때의 유의점(세션 관리)

- 세션 장비는 2, 3층 계층 장비와 달리 세션을 이해하고 세션 테이블을 유지한다.
- 애플리케이션의 세션 시간과 서비스 방향성을 고려하고 비대칭 경로를 피하는 것이 중요하다.

### 6.4.1 세션 테이블 유지, 세션 정보 동기화

- 종단 장비에서 통신을 시작하면 중간에 있는 세션 장비는 세션 상태를 테이블에 기록한다.
- 통신이 없더라도 통신이 정상적으로 종료되지 않았다면 일정 시간 동안 세션 테이블을 유지한다.
- 문제는 애플리케이션은 세션이 살아있다고 생각하는데, 중간 장비 세션 타임아웃이 먼저 만료될 수 있다.
- 즉, 세션 장비의 세션 타임아웃값이 애플리케이션의 세션 타임아웃값보다 짧으면 통신에 문제가 생긴다.
- 세션 테이블에 세션이 없는 상황에서 SYN이 아닌 ACK로 표시된 패킷이 들어오면 비정상 통신으로 판단하고 패킷을 차단한다.

### 6.4.1.1 세션 장비 운영자 입장

- 가. 세션 만료 시간 증가
    - 애플리케이션 세션 유지 시간보다 장비 세션 유지 시간이 길어야 한다.
    - IP나 포트별로 타임아웃을 다르게 줄 수 있으면 운영 안정성이 올라간다.
    - 전제는 애플리케이션의 세션 유지 시간 정보를 운영자가 알아야 한다는 점이다.
- 나. 세션이 없는 패킷도 통과시키는 예외 옵션
    - 특정 ACK를 허용하는 식의 설정이 있을 수 있다.
    - 보안 약화 위험이 커서 신중하게 다뤄야 한다.

### 6.4.1.2 개발자 입장

- 가. 주기적인 패킷 전송
    - 통신이 없더라도 상태 확인 패킷을 보내 세션이 장비에서 만료되지 않게 한다.
    - 헬스 체크나 더미 패킷 같은 방식으로 구현한다.

### 6.4.2 비대칭 경로 문제

- 이중화된 네트워크에서는 들어올 때와 나갈 때의 경로가 달라질 수 있다.
- 세션 장비는 보통 같은 세션의 양방향 패킷이 같은 장비를 지나야 정상 처리하기 쉽다.
- 용어
    - 대칭 경로: Inbound와 Outbound가 같은 장비를 통과
    - 비대칭 경로: Inbound와 Outbound가 다른 장비를 통과

### 해결 방법 1) 세션 테이블 동기화

- 두 장비가 세션 정보를 공유해 한 장비처럼 보이게 만든다.
- 동기화 지연보다 트래픽 응답이 더 빠르면 문제를 못 막을 수 있다.
- 상대적으로 응답 시간이 긴 구간에서 더 현실적인 선택이 될 수 있다.

### 해결 방법 2) 경로 보정으로 강제 대칭화

- 비대칭으로 들어온 패킷을 세션이 있는 장비 쪽으로 보내도록 조정한다.
- 예시로 MAC 리라이트, 터널링 같은 방식이 있다.
- 추가 처리 때문에 성능 저하나 보안 약화 가능성을 같이 고려해야 한다.

### 6.4.3 하나의 통신에 두 개 이상의 세션이 사용될 때의 고려사항

- 어떤 프로토콜은 하나의 기능을 위해 여러 세션을 쓴다.
- 중간 세션 장비가 이 구조를 이해하지 못하면, 일부 세션만 끊겨도 장애 원인 파악이 어려워지고 복구가 길어진다.
- 대표 예시가 FTP다.
    - 컨트롤 채널과 데이터 채널이 분리된다.

### FTP Active 모드

- 컨트롤은 클라이언트가 서버 TCP 21로 연결한다.
- 데이터 채널은 서버가 클라이언트 쪽으로 새 연결을 여는 형태가 된다.
- 중간에 방화벽이나 NAT가 있으면 반대 방향 연결을 막기 쉬워 추가 처리가 필요하다.
- ALG(Application Layer Gateway)
    - FTP 명령을 해석해 데이터 채널을 인지하고 방화벽이나 NAT 처리를 자동으로 맞춰주는 기능이다.

### FTP Passive 모드

- 서버가 데이터 채널에 사용할 포트를 알려주고, 클라이언트가 그 포트로 연결을 시작한다.
- 장점
    - 클라이언트 쪽 방화벽이나 NAT 환경에서 동작이 더 수월하다.
- 주의점
    - 서버 쪽 방화벽에서는 데이터 포트 범위를 열어줘야 한다.
    - 운영에서 Passive 데이터 포트 범위를 관리해야 한다.
