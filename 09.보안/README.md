# 09. 보안

- 이 장은 IT 환경에서 반드시 고려해야 하는 보안의 개념과, 네트워크 관점에서 주로 사용하는 보안 장비와 기술을 정리한 장이다.
- 보안은 특정 직군의 전유물이 아니라 개발자, 서버 엔지니어, 네트워크 엔지니어가 함께 이해하고 설계해야 하는 공통 영역이다.

## **9.1 보안의 개념과 정의**

### **9.1.1 정보 보안의 정의**

- 보안은 사고 없는 상태를 유지하기 위해 위험을 예방하고, 사고가 나면 피해를 최소화하며, 복구 가능한 상태를 유지하는 활동으로 이해할 수 있다.
- IT에서 정보 보안은 정보가 수집, 저장, 처리, 전송, 제공되는 전 과정에서 위험으로부터 보호하는 것을 뜻한다.
- 보안의 필수 요소는 다음 3가지로 정리할 수 있다.
    - 기밀성(Confidentiality)
        - 인가되지 않은 사용자가 정보를 보지 못하도록 하는 모든 작업을 뜻한다.
        - 대표적인 수단은 암호화이다.
    - 무결성(Integrity)
        - 정보가 정확하고 완전한 상태로 유지되도록 하는 모든 작업을 뜻한다.
        - 고의 훼손, 중간 변조, 일부 누락이 발생했는지 식별할 수 있어야 한다.
        - 해시 함수(MD5, SHA 등)처럼 변경 여부를 확인하는 방식이 대표적이다.
    - 가용성(Availability)
        - 정보가 필요할 때 접근 가능하도록 보장하는 작업을 뜻한다.
        - 보안은 막는 것만이 아니라 서비스가 정상 제공되는 상태도 포함한다.
- 3요소 외에 보안에서 자주 언급되는 요소가 있다.
    - 진정성(Authenticity), 책임성(Accountability), 부인 방지(Non Repudiation), 신뢰성(Reliability) 등이 추가로 언급된다.

### **9.1.2 네트워크의 정보 보안**

- 네트워크 관점의 정보 보안은 다음을 막는 데 초점이 있다.
    - 수집된 정보를 훼손, 변조, 유출하는 행위
    - 정보 시스템을 공격해 유출시키거나 사용할 수 없게 만드는 행위
- 네트워크는 정보가 복제되고 이동되는 통로이므로, 통제 장치가 없으면 공격 표면이 크게 확대된다.
- 네트워크 보안은 일반적으로 외부로부터 내부 네트워크를 보호하는 것을 1차 목표로 둔다.

### **9.1.3 네트워크 보안의 주요 개념**

- 네트워크를 구분하는 기본 개념이 있다.
    - 트러스트(Trust) 네트워크
    - 언트러스트(Untrust) 네트워크
    - 내부 네트워크이지만 외부 사용자에게 공개해야 하는 서비스 네트워크는 DMZ로 분리한다.
        
        <img width="738" height="406" alt="image" src="https://github.com/user-attachments/assets/bd1370bb-2909-42cd-aff8-65a8a6e59a2f" />
        
- 트래픽의 방향과 용도에 따라 보안 영역이 달라진다.
    - 인터넷 시큐어 게이트웨이(Internet Secure Gateway)
        - 트러스트(또는 DMZ)에서 언트러스트로 나가는 통신을 통제하는 성격이 강하다.
    - 데이터 센터 시큐어 게이트웨이(Data Center Secure Gateway)
        - 언트러스트에서 트러스트(또는 DMZ)로 들어오는 통신을 통제하는 성격이 강하다.

### **9.1.3.1 네트워크 보안 정책 수립에 따른 분류**

- 보안 정책은 화이트리스트 기반과 블랙리스트 기반으로 구분할 수 있다.
    - 화이트리스트(White List)
        - 문제 없다고 명확히 판단되는 통신만 허용하는 방식이다.
        - 정책 수립을 위해 통신 정보를 상세히 알아야 하고, 통제가 세밀해 관리 부담이 커질 수 있다.
    - 블랙리스트(Black List)
        - 문제가 있다고 판단된 대상만 차단하는 방식이다.
        - 공격 패턴 데이터베이스를 최신으로 유지하는 운영이 중요하다.
        - IPS, 안티바이러스, WAF 등은 시그니처 기반 블랙리스트 방어가 대표적이다.
- 공격 패턴을 시그니처(Signature)로 정의하고 데이터베이스화해 탐지하는 방식이 자주 사용된다.

### **9.1.3.2 정탐, 오탐, 미탐**

- 보안 장비 탐지 결과는 다음 4가지로 정리된다.
    - 정탐(True Positive)
    - 오탐(False Positive)
    - 정탐(True Negative)
    - 미탐(False Negative)
        
        <img width="424" height="246" alt="image" src="https://github.com/user-attachments/assets/b25bf176-7b28-41e0-ad3a-cb4adc7fdb54" />
        
- 운영에서는 오탐을 줄이기 위한 튜닝과, 미탐을 줄이기 위한 공격 데이터베이스 갱신이 모두 중요하다.
- 제로데이(Zero Day)처럼 데이터베이스에 반영되기 전 공격은 미탐 위험이 커진다.

### **9.1.4 네트워크 정보 보안의 발전 추세와 고려사항**

- 네트워크 보안 장비와 서비스는 외부 변화와 내부 변화에 의해 발전한다.
    - 외부 변화: 인프라, 서비스 형태의 변화로 인해 보안도 따라 바뀌어야 한다.
    - 내부 변화: 해킹 기법 발전에 대응하기 위해 새로운 장비와 서비스가 발전한다.
- 공격이 복잡해지며 한 대의 장비로 모두 해결하기 어렵고, 여러 보안 장비와 솔루션이 협업하는 방향으로 발전한다.

## **9.2 보안 솔루션의 종류**

- 보안 솔루션은 어떤 구간에서 무엇을 방어할 것인가에 따라 여러 형태로 배치된다.
- 데이터 센터에서는 인라인 구조로 장비를 단계적으로 배치해 방어 범위를 확장한다.
- 주요 장비 흐름 예시는 다음과 같이 이해할 수 있다.
    - DDoS 방어 장비(프로파일링) → 방화벽(IP, 포트 제어) → IPS(시그니처) → WAF(시그니처) → 서버
        
        <img width="880" height="364" alt="image" src="https://github.com/user-attachments/assets/c45fd922-f3cc-43ce-a937-b56af2fa2a93" />
        

### **9.2.1 DDoS 방어 장비**

- DDoS는 다수의 봇을 이용해 분산 공격을 수행해 정상 서비스 제공을 방해하는 공격 기법이다.
- DDoS 방어 장비는 보통 데이터 센터 네트워크 경계에서 볼류메트릭 공격을 우선 완화하려는 목적이 크다.

### **9.2.2 방화벽**

- 방화벽은 3계층과 4계층 정보를 기반으로 정책을 세워 허용하거나 거부하는 패킷 필터링 장비이다.
- 최근 장비는 전용 칩(ASIC, FPGA 등)을 이용해 고성능 환경에서도 사용 가능하도록 발전한다.

### **9.2.3 IDS, IPS**

- IDS(Intrusion Detection System)는 탐지에 초점을 맞춘 침입 탐지 시스템이다.
- IPS(Intrusion Prevention System)는 인라인에서 공격을 탐지하고 차단하는 침입 방지 시스템이다.
- 최근에는 애플리케이션 공격 방어 장비를 포함해 IPS로 통칭하는 추세이다.

### **9.2.4 WAF**

- WAF(Web Application Firewall)는 HTTP, HTTPS 같은 웹 프로토콜 기반 공격을 방어하는 웹 서버 전용 보안 장비이다.
- 형태는 전용 장비, 웹 서버 플러그인, ADC 플러그인, 프록시 장비 플러그인 등으로 제공된다.
- IPS 회피 공격(Evasion Attack)처럼 애플리케이션 레벨 특성이 있는 공격을 방어하는 역할을 가진다.

### **9.2.5 샌드박스**

- 샌드박스는 악성 코드의 실행 행위를 격리된 환경에서 관찰해 탐지하는 방식의 대표 장비이다.
- 기존 장비 우회가 늘어나는 상황에서, 여러 보안 장비를 보완하는 방식으로 활용된다.

### **9.2.6 NAC**

- NAC(Network Access Control)은 네트워크에 접속하는 장치를 제어하기 위한 솔루션이다.
- 인가된 사용자만 내부망에 접속하도록 통제하고, 승인 실패 사용자는 접속을 차단한다.

### **9.2.7 IP 제어**

- IP 제어는 할당된 IP를 관리하고 추적하며, 의도되지 않은 IP 할당이나 사용을 통제하려는 요구에서 발전한 솔루션이다.

### **9.2.8 접근 통제**

- 운영자가 서버나 장비에 직접 접근해 작업하면 작업 추적과 감사가 어렵다.
- 이를 해결하기 위해 직접 접근을 막고, 작업 추적과 감사를 할 수 있는 접근 통제 솔루션이 사용된다.
- 대표 구현 형태로 배스천 호스트(Bastion Host) 기반이 있다.

### **9.2.9 VPN**

- VPN 장비는 사용자 기반 VPN 서비스를 제공하는 장비이다.
- 과거에는 전용 장비가 많았으나, 방화벽이나 라우터 장비에 포함되는 경우도 많다.
- 가장 많이 사용하는 VPN 기술로 IPSEC과 SSL이 있다.
    - IPSEC은 주로 네트워크 간 연결에 사용한다.
    - SSLVPN은 주로 사용자가 내부 네트워크에 접속할 때 사용한다.

## **9.3 방화벽**

### **9.3.1 방화벽의 정의**

- 방화벽은 네트워크 중간에 위치해, 사전에 주어진 정책 조건에 맞추어 트래픽을 허용하거나 차단하는 장비이다.

### **9.3.2 초기 방화벽**

- 초기 방화벽은 세션을 고려하지 않고 단순히 정책에 따라 패킷을 필터링하는 방식이었다.
- 이러한 방화벽을 스테이트리스(Stateless) 또는 패킷 필터(Packet Filter) 방화벽이라고 한다.
- 패킷 필터 방화벽은 특정 구간에서 간단한 정책을 정의할 때 유리하지만, 인터넷처럼 불특정 다수 대상 정책에서는 룰셋이 복잡해지고 보안이 약화될 수 있다.
- 5-튜플(5-Tuple) 조건이 정책의 핵심 기준이다.
    - Source IP, Destination IP, Protocol, Source Port, Destination Port이다.

### **9.3.3 현대적 방화벽의 등장(SPI 엔진)**

- 패킷 필터의 한계를 극복하기 위해 상태 기반 방화벽이 등장한다.
- 현재 일반적으로 방화벽이라 부르는 장비는 상태 기반 패킷 검사(SPI, Stateful Packet Inspection)를 포함한다.
- 상태 기반 방화벽은 패킷의 인과 관계와 방향성을 이해해 정책을 적용할 수 있다.
- 내부에서 외부로 나가는 요청과, 외부에서 내부로 들어오는 응답을 구분해 정상 통신을 처리할 수 있다.

### **9.3.4 방화벽 동작 방식**

- 방화벽은 대체로 세션 테이블과 포워딩 테이블을 확인하며 패킷을 처리한다
- 패킷 처리 흐름을 간단히 정리하면 다음과 같다.
    
    <img width="966" height="614" alt="image" src="https://github.com/user-attachments/assets/9c5ebf65-24c1-488c-8369-926bb7aea502" />
    
    1. 패킷 유입 시 세션 상태 테이블을 확인한다.
    2. 세션 정보가 있으면 포워딩 테이블을 확인한다.
    3. 세션 정보가 없으면 방화벽 정책을 확인한다.
    4. 정책을 순서대로 확인한 뒤 없으면 암시적인 거부(Implicit Denial)로 차단한다.
    5. 허용 규칙이면 세션 테이블에 기록한다.
    6. 포워딩 테이블을 확인한다.
    7. 포워딩 정보가 있으면 해당 인터페이스로 패킷을 포워딩한다.
    8. 포워딩 정보가 없으면 패킷을 폐기한다.
- SPI 기반 방화벽은 5-튜플뿐 아니라 OSI 3계층과 4계층의 상세 필드도 함께 확인한다.
- TCP Anti-Replay 같은 기능으로 비정상 세션 변화를 일부 방어할 수도 있다.

### **9.3.5 ALG**

- 상태 기반 방화벽이 3계층과 4계층을 이해해도, 애플리케이션 계층 프로토콜을 이해하지 못해 통신이 실패하는 경우가 있다.
- 대표 예시로 FTP가 있다. FTP는 컨트롤과 데이터가 분리되고, 액티브 모드에서는 데이터 연결 방향이 초기 접속 방향과 달라질 수 있다.
- ALG(Application Layer Gateway)는 이런 문제를 해결하기 위해 방화벽이 프로토콜을 인지하고 세션을 자동으로 열어주는 기능이다.
- ALG는 편리하지만 모든 프로토콜에 적용할 수 있는 만능 해결책이 아니며, 최근에는 NAT 환경을 고려한 애플리케이션 개발과 STUN 같은 홀 펀칭 기술이 발전해 ALG 의존이 줄어드는 추세이다.

### **9.3.6 방화벽의 한계**

- 방화벽이 발전했어도 OSI 3계층과 4계층 중심이라는 한계가 있다.
- 애플리케이션 취약점 기반 공격은 방화벽만으로 대응이 어렵다.
- DDoS 같은 대규모 공격은 방화벽의 한계를 드러내며, 별도의 DDoS 방어 체계가 필요하다.
- 방화벽은 NGFW, UTM으로 확장되며 애플리케이션 영역까지 보안을 제공하는 방향으로 발전한다.
- NFV(Network Function Virtualization)처럼 보안 장비를 가상화해 적용하려는 흐름도 있다.
- 방화벽은 제조사마다 패킷 처리 순서가 다르므로 도입과 운영 전에 Packet Processing Flow 문서를 확인해야 한다.

## **9.4 IPS, IDS**

### **9.4.1 IPS, IDS의 정의**

- IDS(Intrusion Detection System)는 침입 탐지에 초점을 둔 시스템이다.
    - 트래픽을 복제해 검사하고, 침입 여부를 판단해 알람을 보내는 구조이다.
    - 일부 기능으로 세션 리셋 등이 있을 수 있다.
        
        <img width="996" height="364" alt="image" src="https://github.com/user-attachments/assets/ce6fa688-52c6-44fe-b9d1-afcdff10af05" />
        
- IPS(Intrusion Prevention System)는 침입 방지에 초점을 둔 시스템이다.
    - 트래픽이 지나가는 인라인 구간에 장비를 배치해 적극적으로 차단한다.
        
        <img width="828" height="184" alt="image" src="https://github.com/user-attachments/assets/3961f05d-e40a-4986-9d64-3bba9215869d" />
        
- 대표적으로 호스트 기반 IPS와 네트워크 기반 IPS가 있다.
- 클라우드 환경에서는 HIPS 배치가 쉽지만, 자원 공유와 장애 주체 파악 문제 등으로 NIPS로 전환하는 추세이다.

### **9.4.2 IPS, IDS의 동작 방식**

- IPS는 기본적으로 공격 데이터베이스(Signature)를 이용하는 패턴 매칭 방식이 중심이다.
- 추가 기법으로 프로토콜 어노멀리, 프로파일 어노멀리 같은 방식이 있다.

### **9.4.2.1 패턴 매칭 방식**

- 공격이나 취약점 기반 공격 방식을 시그니처로 만들어 탐지한다.
- IPS는 최신 공격 정보를 빠르게 데이터베이스에 반영하는 운영이 중요하다.
    
    <img width="634" height="344" alt="image" src="https://github.com/user-attachments/assets/51c3fa96-284b-4c84-8092-2819ff0787df" />
    

### **9.4.2.2 어노멀리 공격 방어**

- 패턴 매칭은 공격이 알려지기 전에는 대응이 어렵고, 변종 확산이 빠르면 방어가 늦어질 수 있다.
- 이를 보완하기 위해 공격이라고 명확히 단정되지 않더라도 기준 이상으로 이상하면 차단하는 어노멀리 기반 방어가 등장한다.
- 어노멀리는 프로파일 어노멀리와 프로토콜 어노멀리로 구분한다.
    - 프로파일 어노멀리
        - 정해진 기준과 다른 행위가 일어나면 공격으로 판단한다.
        - 예를 들어, 평소 트래픽 기준과 다른 행위를 이상으로 판단한다.
    - 프로토콜 어노멀리
        - 잘 알려진 포트와 실제 통신 프로토콜이 다르면 의심할 수 있다는 관점이다.

### **9.4.3 IPS, IDS의 한계와 극복(NGIPS)**

- IPS는 빠른 속도로 애플리케이션 레벨까지 확인하기 어려워 플로우 엔진을 사용한다.
- IPS는 오탐이 많을 수 있어 초기 튜닝이 오래 걸리고, 지속적인 운영이 필요하다.
- 오탐과 알람 과다로 인해 제대로 사용하지 못하는 경우가 생길 수 있다.
- 이를 개선하기 위해 NGIPS(Next Generation IPS) 개념이 등장한다.
- IPS 단독 시장은 줄고, 방화벽이 NGFW나 UTM으로 발전하며 IPS 기능이 통합되는 흐름이다.
- IPS 공격 데이터베이스를 얻기 위한 방법으로 허니팟(Honeypot)이라는 기법을 이용한다.
    - 취약한 시스템을 의도적으로 공격 대상으로 노출하고 공격을 로깅해 분석한다.

## **9.5 DDoS 방어 장비**

### **9.5.1 DDoS 방어 장비의 정의**

- 초기 DDoS는 시스템이나 네트워크 장비 취약점 타깃이 많았고, 이후 인프라 기반 서비스 영역까지 공격이 확대되었다.
- 패치만으로 막기 어려운 대규모 공격을 방어하기 위해 DDoS 방어 장비가 등장했다.
- DDoS 방어 장비는 트래픽 프로파일링 기반 방어를 주로 사용하며, 공격 정보를 수집한 데이터베이스를 활용하기도 한다.

### **9.5.2 DDoS 방어 장비 동작 방식**

- DDoS 방어 서비스는 다음 형태가 있다.
    - 클라우드 기반 서비스
    - 회선 사업자 방어 서비스
    - 데이터 센터 내부 설치 방식

### **9.5.3 DDoS 공격 타입**

- DDoS 공격은 크게 다음 3가지로 정리한다.
    - 볼류메트릭 공격(Volumetric Attack)
    - 프로토콜 공격(Protocol Attack)
    - 애플리케이션 공격(Application Attack)
    
    <img width="978" height="634" alt="image" src="https://github.com/user-attachments/assets/c3a6d611-0e59-43ad-a04f-5058f00fa100" />
    

### **9.5.4 볼류메트릭 공격**

- 회선 사용량을 과도하게 발생시켜 회선을 사용하지 못하도록 방해하는 공격이다.
- 좀비 PC를 많이 확보해 공격을 수행하는 형태이다.
- 공격자가 적은 트래픽으로 중간 리플렉터를 이용해 트래픽을 증폭시키는 증폭 공격(Amplification Attack)도 있다.
- 혼자 방어가 어렵기 때문에 ISP를 통한 방어 또는 클라우드 DDoS 솔루션을 고려해야 한다.

## **9.6 VPN**

### **9.6.1 VPN 동작 방식**

- VPN은 공중망을 이용해 논리적으로 전용선처럼 구성하는 기술이며, 이 논리적 통로를 터널(Tunnel)이라고 한다.
- VPN은 터널링만 제공하면 충분하지 않고, 공중망에서 안전하게 통신하기 위해 암호화와 인증 같은 보안 강화 기술이 필요하다.
    
    <img width="812" height="392" alt="image" src="https://github.com/user-attachments/assets/589df23c-0077-4a1e-9ffb-1d35b1963a4a" />
    
- 과거에는 PPTP, L2TP, GRE처럼 암호화를 강하게 지원하지 않는 기술도 사용되었지만, 최근에는 IPSEC 보안 기술을 함께 사용하는 추세이다.
- 전용 회선을 쓰더라도 회선 자체는 데이터가 그대로 흐를 수 있어, 추가로 전용 회선 위에 VPN을 구성해 암호화를 적용할 수도 있다.
- 본사와 지사 간 네트워크 연결에는 IPSEC VPN 기술이 사용된다. (네트워크 대 네트워크)
    
    <img width="814" height="196" alt="image" src="https://github.com/user-attachments/assets/9def226d-9944-44cd-b4cd-728ee126fe79" />
    
- 개인 사용자가 본사 네트워크에 접속하는 경우에는 SSLVPN 기술이 사용된다. (PC 대 네트워크, 모바일 대 네트워크)
    
    <img width="646" height="212" alt="image" src="https://github.com/user-attachments/assets/a60bf41c-7ec4-4704-954b-52fcc3b08c7e" />
    
- VPN은 일반적으로 다음 3가지 형태로 구현된다.
    - Host to Host 통신 보호 - 잘 사용하지 않음
    - Network to Network 통신 보호 - IPSEC 프로토콜 스택을 가장 많이 사용
    - Host가 Network로 접근할 때 보호 - IPSEC과 SSL 프로토콜을 범용적으로 사용
- VPN은 사이트 우회 목적 외에도 공공 무선망 같은 환경에서 암호화를 통해 공격을 원천 방어하는 관점에서 유용하다.
